Self-audit of samedaydesk.com

This document is the complete public sample of the paid SameDayDesk audit. It was run against our own production site, and it was published while every finding below was still live and reproducible by a stranger.

This document is the sample of the paid production audit. Later fixes to the live site do not rewrite it. Retests are section 13 addenda, and they change only the status field of a card.

2. Executive summary

Why this exists. A buyer deciding whether to pay for an audit should be able to read the whole artifact first. This is that artifact, run on the vendor's own production site so the sample cannot be a staged demo.

What was tested. The homepage as first-byte HTML and as rendered DOM, one further application route as first-byte HTML, and the public machine files: llms.txt, the agent card, robots.txt, sitemap.xml, the resources page, and one standalone sales page. Full list in section 4.

What was found. Five High, one Medium, one Info. The Highs are: the first-byte JSON-LD catalog (SDD-2026-001), the first-byte noscript catalog (SDD-2026-002), a tool-count disagreement between machine files (SDD-2026-003), a brand tagline that sells the service line this company is leaving (SDD-2026-004), and one price point published with two different delivery times on two live pages (SDD-2026-005).

Verdict as of the stamp. This site does not meet its own machine-surface consistency rule. It is not a security finding, it is not a data exposure, and no user task on the site is broken by any card in this report.

What happens next. The four catalog and identity findings carry a 14-day clock to 2026-09-02 (section 10). The architecture card that causes first-byte drift carries a later named date, because pretending a rendering change is a 14-day job would be dishonest.

Residual risk: this is a structured sample of one homepage plus the named machine files, not a site-wide conformance review. Surfaces outside section 4 were not read.

3. Scope and method

In scope

  • https://samedaydesk.com/ first-byte HTML (fetched, JS never executed)
  • https://samedaydesk.com/ rendered DOM (headless Chrome, JS executed)
  • The JSON-LD blocks inside that first-byte HTML
  • The noscript block inside that first-byte HTML
  • The visible brand tagline, document title, and Open Graph copy
  • https://samedaydesk.com/llms.txt
  • https://samedaydesk.com/.well-known/agent-card.json
  • https://samedaydesk.com/robots.txt and https://samedaydesk.com/sitemap.xml
  • https://samedaydesk.com/resources.html
  • https://samedaydesk.com/ai-visibility-audit.html
  • https://samedaydesk.com/x402 first-byte HTML, as one sample of an application route
  • The x402 resource manifest that the machine files above describe, fetched from the gateway host

Out of scope

Authenticated pages, the checkout and payment flow, email, third-party analytics, the remote MCP endpoint internals, the hosted documentation directories, and every locale other than the default. They are out because this sample is bounded to the surfaces that publish what the business sells; each of them can be bought as an extension, and none of them was read.

Conformance target

The bar here is the product rubric, not an external standard: machine surfaces agree with each other, first-byte and rendered surfaces agree on what is sold, and no crawler-visible copy offers a service line the business is not selling. This report is not a WCAG conformance claim, not a penetration test, not a SOC 2 statement, and not a security advisory.

Baseline

Logged out, no cookies, cold cache, IPv4 egress, default locale. Two user agents were used: SameDayDeskAudit/0.1 (+https://samedaydesk.com/audit) for every capture, and OAI-SearchBot/1.4 for one crawler-parity capture of the homepage. JS off for all first-byte artifacts; JS on for the single rendered artifact.

5. What already meets the bar

  • HTTPS on every captured URL, with www answering HTTP 301 to the apex host.
  • No crawler cloaking: the plain-agent capture and the OAI-SearchBot/1.4 capture of the homepage are byte-identical (same SHA256), so the site does not serve search fetchers a different document.
  • robots.txt allows the AI crawlers that matter for this product (GPTBot, OAI-SearchBot, ChatGPT-User, ClaudeBot, PerplexityBot, Perplexity-User, Google-Extended, Applebot-Extended, CCBot) and points at the sitemap.
  • The public machine files exist and return 200: llms.txt, an agent card, a sitemap.
  • All 44 URLs in the sitemap answer 200 to a plain fetch (with the caveat in SDD-2026-006).
  • The health endpoint answers 200 with a JSON body.
  • The homepage carries JSON-LD at all, and it parses. Most sites in this product's sample do not.

9. First byte versus rendered DOM

How first byte was taken. curl -sS -D headers -o body -A "SameDayDeskAudit/0.1 (+https://samedaydesk.com/audit)" https://samedaydesk.com/ with curl 8.14.1. No JS executed at any point.

How the rendered DOM was taken. Google Chrome 151.0.7922.71 headless with --dump-dom and an 8 second virtual time budget, same URL, JS executed.

What a fetcher that does not run JS receives: a 12,418 byte document whose entire commercial content is the JSON-LD catalog of SDD-2026-001 and the noscript catalog of SDD-2026-002.

What a human with JS receives: a 42,622 byte DOM with 12 purchasable services. Both documents sell the same retired service line, so on this site the rendered page is not the current one either. Where they differ is completeness: the rendered page carries 4 services the machine catalog omits.

Automated readability and accessibility tooling usually tests the rendered DOM. This product also tests the unrendered bytes, because that is where the catalog in SDD-2026-001 lives and a rendered-only test would report this homepage as consistent with itself.

Replay script

replay.sh runs all of the above and prints, per finding, whether the T0 predicate still matches production. It exits 1 while any of the four T0 High predicates still match, and 0 once none of them do. That is deliberate: while the clock is running, the script a buyer downloads should fail.

curl -sS https://samedaydesk.com/audit/samedaydesk/2026-08-19/replay.sh -o replay.sh
bash replay.sh ; echo "exit=$?"

Evidence pack

Every captured body, every response header block, the extracted JSON-LD, the extracted noscript, the sitemap status sweep, and the capture conditions: evidence/, hashed in SHA256SUMS.txt, described in CAPTURE-MANIFEST.md. Captured bodies carry a .txt extension so this directory serves frozen evidence as text and never as a second live copy of the site. The bytes are unmodified, so the hashes match what the live URLs returned.

What was not run

No Lighthouse, no axe, no WAVE, no authenticated surface, no checkout, no email, no mobile emulation, no second locale, no repeat capture on another date. Method version 1.0.0, so a later audit of this same site can be compared against this one.

12. Limits and non-claims

  • This is a structured sample of one homepage plus named machine surfaces, not a site-wide conformance statement.
  • Automated checks miss issues. The absence of a card here is not a pass.
  • Point in time. The live site will change; this file will not.
  • Not a penetration test, not SOC 2, not a legal WCAG statement, not a security advisory.
  • Known unknowns: authenticated pages, the payment path, email deliverability, the MCP endpoint internals, other locales.
  • No claim is made here about what any AI engine currently answers about this business. That measurement is a different artifact with a different method.
