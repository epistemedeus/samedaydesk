# Inspected x402 route feed

Build-time inspection list at `/x402/verified.json`, generated by
`client/scripts/writeVerifiedFeed.mjs` from the committed SameDayDesk
seller-conformance crawl. Inspection evidence only. Not a certificate.

## Operator refresh (publish candidate)

Manual, no cron. Reuses the existing allowlisted SameDayDesk example URLs and
validation modules. Live mode writes an observation report plus a separate candidate feed;
it never replaces production `verified.json` until final review.

```bash
npm run verified-feed:refresh -- --fixtures --fixture extract-current --as-of 2026-09-03T12:00:00.000Z
```

The fixture command is a synthetic test: it writes an explicitly fixture-mode
observation report, never a publishable feed file. Generation remains testable
in memory. To produce a candidate, run a one-route read-only live check (no
wallet, no credentials, no payment):

```bash
npm run verified-feed:refresh -- --live --live-route-limit 1
```

Default outputs:

- `client/tmp/x402/verified.observations.json`
- `client/tmp/x402/verified.candidate.json` (live mode only, when at least one current row validates)

### Evidence semantics

| Observation status | Meaning | Feed effect |
| --- | --- | --- |
| `current` | Successful unpaid 402 observation at refresh `asOf` | May enter the candidate feed with `lastVerified = asOf` |
| `stale` | Prior crawl evidence exists, but it was not re-observed at `asOf` | Prior `lastObservation` kept on the report only; cannot keep a current verified claim |
| `unknown` | No prior live unpaid-402 evidence | No current claim |
| `failed` | Timeout, redirect, invalid JSON, SSRF block, or non-402 | `lastObservation` stays null; failure recorded separately |

Never invent a fresh `observedAt` / `lastVerified` from old evidence. Existing
Bazaar rows are reused as-is and re-checked against the seven-day freshness
bound at refresh time; their timestamps are not rewritten.

## Who appears

Only current SameDayDesk routes that have a live unpaid 402 verification
time and a 64-character contract hash. `crawl.findings` and repair briefs
never enter this feed.

## Verified badge

A row is `verified` only when all of the following hold at crawl time:

1. Live unpaid 402 contract (`price.source = live_unpaid_402`) with a
   verification timestamp and contract hash.
2. The operation was observed in the current OpenAPI document
   (`agreement.openapi`).
3. A matching CDP Bazaar row agrees on resource, seller, amount, network,
   and output keys.
4. That Bazaar observation is fresh.

## Bazaar freshness bound

`BAZAAR_FRESHNESS_MS` in `client/scripts/generateVerifiedFeed.mjs` is seven
days:

```
7 * 24 * 60 * 60 * 1000
```

Freshness compares Bazaar `lastUpdated` to the crawl timestamp. The
observation time is copied onto each row as `bazaarObservedAt`. If the
Bazaar row is missing, disagrees, or is older than seven days, the row is
not `verified`.

## Network

Each row's `network` is a single CAIP-2 identifier such as `eip155:8453`.
Compound values such as "Base or Polygon" or "Base or Solana" are rejected.

## Unchecked routes

Routes that lack a live unpaid-402 verification time or contract hash are
omitted. They are never published as `verified`.
