# Receiving decisions

The exported0.1.0 client and original346 receipts remain historical immutable
evidence. Their native source SHA is retained even when GitHub uses a different
commit wrapper. The new client is needed because executable budget transport
changed. Its source pin identifies committed client bytes, and export fails if
new bytes would borrow an older SHA. Exact archive/readback is separate from
operational production and current grants.

The existing work-cell/FoundryBoundary transaction seam still owns authorization,
revision/fence, cancellation and expiry. The adapter uses the existing
`correspondence_idempotency` scopes for immutable request/result/execution
receipts. The failure-injected release test proves that result insertion and
checkpoint roll back together, leaving the committed claim and reservation.
Revocation between claim and completion prevents output retention. Original
deadline/caps cannot be renewed by a new client process. After unknown physical
execution, recovery reads any committed result; it cannot silently rerun the
child. This conservative recovery behavior is a material receiving change.

The client sends consumed bytes after serializing each request. The server seeds
that same ledger, debits intake/PG/child/output, and returns its cumulative charge
before response intake. Missing/backward successful budget receipts are refused.
Original reduced caps and a conservative final-admission charge are retained for
cold recovery. Public evaluation does not admit work. Optional export separately
requires current project/job writer authority, purpose, opt-in and retained digest;
the existing scrubber preserves useful selected fields with unverified trust.

The source work-brief parser omitted ordinary Update/Add instructions. The new
caller case reproduced zero actions; its owning regression now preserves both
actions and the untrusted original source body. No code or instruction execution
authority is derived from that body. The projection regression remains at its
original owner and is included in the122 recipe/reuse checks.

The inherited readiness assertion required literal MCP tool names plus an
unpublished agent-readiness URL in human discovery files. It fails on detached
unchanged685f90f6. The corrected owner verifies actual tools/list, agent card and
verifier equality and the existing MCP/for-agents/llms discovery links. No human
file was changed to satisfy the stale assertion.

Native receiving, loopback source hosting, anonymous production discovery,
retained task observations, authorized export, contribution/acceptance and
settlement are separate facts. Review/contributor labor, cost savings, demand,
all-time revenue and outside use were not measured. The compact result states
the remaining Root publication/enrollment and a supported next visitor action.
